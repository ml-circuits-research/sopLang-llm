Language

SOP Lang

SOP Lang is the executable intermediate representation of this project. The student model writes it, and the runtime executes it. The language is intentionally small: its basic unit is a wire, and extensibility comes from wire commands rather than from a growing surface grammar.

Declarations and bodies

A wire declaration begins at the start of a line with @, followed by a wire name and a wire command. Everything until the next valid declaration belongs to the wire's body. A body may contain JavaScript, plain text, JSON, a neural instruction, or command-specific configuration, so the grammar stays uniform while commands stay flexible.

@selected jsEval
return $rows.filter(row => row.enabled === true);

@total jsEval
return $selected.reduce((sum, row) => sum + row.amount, 0);

@output jsEval
return JSON.stringify({
  count: $selected.length,
  total: $total
});

In this program rows is an input wire supplied by the wrapper. selected depends on rows, total depends on selected, and output depends on both values its code uses. The textual order of declarations is not the execution order. The runtime extracts dependencies, builds a directed graph, validates that the active graph is acyclic, sorts it topologically, and executes each wire only after its value dependencies are valid.

Parser boundary rule

A line that begins in column one with a valid @name command starts a new wire. A body that must literally contain such a line escapes it as \@name command, and the runtime removes the escape before the body reaches the command. Wire identifiers use a conservative ASCII grammar in the reference implementation so they can be bound predictably inside JavaScript, while values themselves can contain arbitrary Unicode.

Value references and conditionality

The canonical value reference is $name. There is no privileged conditional or looping primitive. A local conditional belongs in JavaScript or in the implementation of a custom wire command, and it selects among values that are already dependencies of the wire. Structural conditionality, which changes which subgraph should exist at all, uses the metaprogramming API to create or redefine wires. The runtime then validates the new graph revision and sorts it again.

Dependency analysis

Dependency extraction is not a naive regular expression over body text. In jsEval, $rows used as an identifier is a dependency, while the characters "$rows" inside a string literal may be data or code to be emitted later. The JavaScript implementation lexes the body well enough to find value references outside quoted literals and comments, and other wire types define their own analyzer. Every registered command therefore carries both execution semantics and dependency-analysis semantics, and the runtime asks a command which values and structural definitions it reads before scheduling it.

Output convention

A circuit's output is a convention rather than special control flow. The runtime returns the value of a configured output wire, commonly named output, and that wire can have any command type. When a caller requires JSON, a final jsEval constructs and serializes the object deterministically. When a caller requires a typed object, the runtime validates the output value against a declared JSON Schema before returning it, so formatting correctness is guaranteed independently of the semantic correctness of upstream analysis.

Metaprogramming and templates

A static directed acyclic graph is enough when the complete set of subproblems is known in advance. Real tasks often reveal structure only after data is available: a query returns an unknown number of groups, a legal analysis discovers exceptions that each need separate verification, or a debugging task produces a new hypothesis after a test fails. A jsEval wire can stage changes to the circuit itself through a transactional API.

circuit.addWire(name, { command, body, metadata });
circuit.redefineWire(name, { command, body, metadata, expectedDefinitionHash });
circuit.invalidateWire(name, { reason });
circuit.invalidateDownstream(name, { reason });
circuit.instantiateTemplate(templateName, bindings, { prefix });
circuit.getDefinition(name);
circuit.listDefinitions({ prefix });
circuit.commit({ key, result });

The API does not expose an unrestricted value read. Values enter JavaScript through $wire dependencies so the graph remains a truthful description of causality. All write methods append to a transaction buffer, and circuit.commit asks the runtime to validate and publish the buffered operations at the epoch boundary. Newly created wires are not executed in the stale schedule: the runtime applies the transaction, re-analyzes dependencies, verifies acyclicity, increments the circuit revision, and starts the next epoch.

A template is a reusable SOP Lang fragment with named parameters and hygienic internal wire names. Templates represent patterns such as map-then-reduce, retrieve-then-verify, or recursive divide-and-analyze, and their source is versioned and inspectable. Recursion emerges as a template instantiating another copy of itself for a smaller subproblem, which means every fixed graph revision stays acyclic and resource bounds such as epoch count, created wires, neural calls, JavaScript time, and template depth stay explicit.

Where the contract lives

The language, scheduling, and transaction semantics are specified in DS002-sop-lang-core. The command vocabulary and the .mjs extension contract are specified in DS004-wire-types. Container commands and their revision semantics are specified in DS005-containers.
