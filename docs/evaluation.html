Evaluation

Evaluation decides whether the system supports or rejects the research thesis. It compares the student against larger direct-answer models and simpler baselines, ablates the parts of the architecture, and reports metrics that separate syntactic validity from semantic correctness. Every reported number traces to a raw per-item record.

Baselines and ablations

The main comparison is factorial rather than anecdotal. At minimum it evaluates the student in direct-answer mode, the same student with SOP Lang, a larger teacher in direct-answer mode, and the larger teacher with SOP Lang where feasible. Long-document experiments add a straightforward chunk-and-merge baseline and a retrieval-based baseline, and structured tasks include direct JavaScript or SQL generation where that is a credible alternative.

Ablations identify which parts of the system matter. Removing explicit decomposition asks the student to generate the whole circuit in one pass. Disabling jsEval forces neural computation for deterministic operations. Removing compiled containers supplies retrieved raw chunks instead. Replacing task-conditioned schemas with a fixed universal schema tests schema planning. Disabling metaprogramming prevents graph expansion after values are known. Removing anti-smoothing audits tests preservation policy. Hiding custom wire descriptions tests memorized command names.

The most important comparison reports total neural tokens, number of calls, runtime cost, and latency together with accuracy, because a recursive small model invoked many times may use more compute than a single large call. Parameter count alone is not an efficiency metric.

Generalization tests

Generalization goes beyond held-out wording. Procedural families hold out operator compositions, dependency depths, branching patterns, tool manifests, and schema shapes. A student trained on circuits up to depth eight is tested at depths sixteen, thirty-two, and sixty-four. A student trained on a set of named tools is tested on semantically similar but renamed tools whose definitions are supplied only through manifests. A student trained on sources up to a hundred thousand tokens is tested on much longer sources while local context stays fixed.

Long-document evaluation varies the location of critical evidence and the number of irrelevant chunks, because position sensitivity and dilution are different effects. A compiled-context system may be robust to position and still suffer when ingestion produces too many noisy records, so container precision and source-recall metrics accompany final accuracy.

Metrics

Final task success is the primary metric when an oracle exists: for a problem set of N items, success is the fraction whose executed final result matches the oracle within the declared tolerance. Circuit parse validity, graph validity, runtime completion, and output-schema validity are reported separately, which prevents a system from looking strong because it produces syntactically beautiful but semantically wrong programs.

Anti-smoothing and novelty

Anti-smoothing is not a philosophical label. Rare-critical loss, exception loss, qualifier loss, minority-position loss, contradiction smoothing, specificity loss, and uncertainty smoothing are scored separately, and preservation checks require identity and relation correctness rather than keyword overlap, because a summary may mention an exception but attach it to the wrong rule. A simple weighted preservation measure over required items is reported by category instead of collapsed into one score.

Novelty distinguishes within-document novelty, novelty relative to a fixed reference corpus, and literature-grounded scientific novelty. Candidate generation, retrieval, filtering, comparison, and reporting are separate wires: numerical similarity, date filters, deduplication, and ranking are symbolic, and neural judgment is reserved for semantic equivalence and contribution classification. Novelty preservation measures which evidence-grounded candidates survive a summary.

Summary and novelty acceptance

Controlled summarization reports inventory recall, selection recall, and realization recall as separate quantities, so a report distinguishes loss inside the compiled inventory from loss in the importance policy and from loss in the wording. Preservation is reported per obligation category with identity and relation correctness rather than keyword overlap, because a summary may name an exception while attaching it to the wrong rule. A repair is accepted only when the full obligation set is re-audited after the repair: a repair that adds one obligation while dropping another, or that strengthens a qualifier, fails, and repair cost is reported together with its side effects.

Novelty evaluation separates candidate recall, retrieval recall, and relationship classification, because a perfect judge cannot identify prior art that retrieval never surfaces. Every novelty record preserves the queries, the indexes searched, the corpus snapshot, the publication cutoff, the number of candidates examined, the comparison method, and the limitations of the search. A conclusion is constrained to the searched corpus, so a report states that no close match was found in the searched corpus rather than asserting historical novelty, and a failure to retrieve a match is recorded as negative evidence rather than as proof of novelty.

Statistical structure

Statistical analysis preserves problem-family structure. When a benchmark contains thousands of easy arithmetic items and only fifty difficult long-document cases, one micro-averaged score hides the research result, so the report uses macro averages by family and difficulty stratum and computes confidence intervals over problem instances or document clusters rather than over individual extracted records that correlate within one book.

Evidence registry and falsification criteria

The evidence registry holds hypotheses, benchmark definitions, experiment manifests, metrics, confidence intervals, plots, failure examples, and limitations. Manuscript tables and figures are generated from per-item records, every quantitative claim references an experiment identifier, and every qualitative example references a source item and a trace. Negative results remain in the registry and influence the discussion.

Predeclared criteria protect the project from narrative drift. The small-model efficiency hypothesis is not supported if the student requires greater total neural compute than the larger baseline for equal accuracy. The compiled-context hypothesis is not supported if ingestion losses make final accuracy worse than a simpler retrieval baseline at similar cost. The unseen-tool hypothesis is not supported if the student fails when command names are randomized despite clear manifests. The anti-smoothing hypothesis is not supported if rare-critical preservation does not improve after controlling for output length and model-call budget.

A negative result remains publishable when it identifies a sharp limitation, for example that sub-billion models learn SOP Lang syntax and deterministic delegation but cannot reliably perform task-conditioned decomposition over ambiguous long documents. The purpose of the system is to make those boundaries measurable.
