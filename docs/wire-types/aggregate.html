Wire types

aggregate

aggregate filters a source list by a declared predicate and reduces the kept records to one scalar — sum, count, min, max, or average — in a single command.

What it does

A filter-then-summarize plan names its predicate and aggregate instead of writing a filter and a reduce. The source is a list of whole numbers; the kept records are the elements that pass the predicate, and the command reduces them to one number.

How it works

The predicate is a tiny declarative form, never a second JavaScript: a comparison against a threshold (above, atLeast, below, atMost) or a divisibility test (divisibleBy), named by exactly one key in the body. A field names which field to compare and reduce for a list of records; without it, the element itself is the value.

The command owns the non-empty and whole-number contract: sum and count reduce an empty kept list to zero, while min, max, and average reject an empty kept list as a structured execution_error. Every reduction runs over numbers and returns a whole number for whole inputs; average returns the exact mean. A malformed predicate or an unknown operation is a validation_error before execution. The command is pure and deterministic (version 1.0.0).

Body syntax

@average aggregate
source: $slots.scores
op: average
predicate:
  atLeast: $slots.minimum

Worked example

A qualifying average over the scores at or above a threshold:

@scores literal
[7, 12, 3, 18, 9]

@minimum literal
5

@qualifying aggregate
source: $scores
op: average
predicate:
  atLeast: $minimum

The predicate keeps [7, 12, 18, 9], and average returns the exact mean 11.5. A sum over the same kept list would return 46, and a count would return 4.
