Wire types

jsEval

jsEval is the universal deterministic escape hatch: it executes JavaScript over declared $wire dependencies in an isolated realm, and may stage graph or container transactions through the runtime API.

What it does

When the remaining subproblem is mechanical — arithmetic, sorting, joins, filtering, aggregation, validation, or serialization — it belongs in a jsEval body. The body runs as an async function body with the declared dependencies as parameters, plus a circuit parameter that exposes the transactional graph API without permitting a hidden value read.

How it works

The body runs in a private guest realm inside a worker thread: a fresh ECMAScript context per call holding only ECMAScript intrinsics, so generated code cannot reach process, the module loader, or any host object. Dependency values arrive as copies, so a guest mutation never reaches a stored value.

The command owns its input/output contract, so a compiled plan never restates it. Before the body runs, the sandbox asserts that every declared dependency is defined and that a dependency named slots carrying a compiled record is a non-empty object. After the body runs, it asserts the result is not null, undefined, or the empty string — the values a downstream wire would read as "nothing was computed". Failures are structured execution_errors naming the wire and the contract clause.

Version 2.1 adds the probe(condition, message) helper: the sandbox defines it in guest scope, so a body writes its own domain assertions as bare probe(...) calls instead of carrying the helper's definition. A failed probe throws and ends the wire as an execution_error.

The transactional circuit API — addWire, redefineWire, invalidateWire, invalidateDownstream, getDefinition, listDefinitions, and commit — records operations in the guest realm and replays them onto the real transaction after the call; an uncommitted transaction never publishes.

Every call is bounded by a JavaScript deadline (default 2000 ms, charged cumulatively against the request budget) and a transaction operation cap. Exhaustion is a structured budget_exceeded outcome; failures are typed validation_error (syntax), execution_error (body failure), and unsupported_value (non-transferable). The command is pure by default but may stage a structural transaction or a container patch (version 2.1.0).

Body syntax

The body is JavaScript; references to other wires use the $name form outside strings and comments.

@selected jsEval
return $rows.filter(row => row.enabled === true);

Worked example

A summarization step that keeps passing rows and asserts at least one survived:

@rows input

@summary jsEval
const kept = $rows.filter((row) => row.score >= 50);
probe(kept.length > 0, "no row reached the passing score");
return { count: kept.length, total: kept.reduce((s, r) => s + r.score, 0) };

The analyzer reads $rows as a dependency, the sandbox asserts the input contract before the body runs, and the probe turns a domain-specific impossibility into a typed failure instead of a wrong-looking value.
