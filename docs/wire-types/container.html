Wire types

container

container declares a typed persistent collection — its kind, schema, identity policy, and merge policy — as a first-class wire value.

What it does

A container is typed persistent state declared as a first-class wire value. The declaration names the collection kind (table, set, or sequence), a record schema, and an identity policy (primaryKey or an identity function); a mergePolicy may override the default reject. The wire's value is the container snapshot, so a reader sees the current revision.

How it works

The declaration is a structural state declaration: the schema and identity policy become trusted runtime state, and the wire reads the container it declares. The analyzer records the declaration wire as both a container read and its own target. The validator requires a kind. On execution the command declares the container (or returns the existing snapshot if it is already declared) and publishes the snapshot. A commit invalidates the declaration wire, so the next epoch returns the new revision. The command is pure (it declares state rather than mutating it) and deterministic (version 1.1.0).

Body syntax

@characters container
kind: table
primaryKey: id
schema:
  type: object
  required: [id, name, sourceSpans]

Worked example

A planning call declares a character table before any source chunk is read:

@characters container
kind: table
primaryKey: id
schema:
  type: object
  required: [id, name, sourceSpans]
  properties:
    id: { type: string }
    name: { type: string }
    aliases: { type: array, items: { type: string } }
    traits: { type: array, items: { type: string } }
    sourceSpans: { type: array }

After the call, this definition is trusted runtime state supplied to ingestion calls. The source chunk remains data; the schema is a system capability and contract.
