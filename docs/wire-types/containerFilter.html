Wire types

containerFilter

containerFilter defines a pure derived view of a source container while retaining provenance.

What it does

Use it to select the records a later step should read, keeping the source revision visible. The body names a source container value and a predicate that runs over a row. It never changes the source container; filters produce derived views only.

How it works

The view's value depends on the source container revision and on any predicate dependencies (the $name references other than row). The predicate runs per row in the isolated guest realm, and the returned view references source record identities and the revision it was computed from, so provenance stays traceable. A filter may read another derived view, so filters compose as ordinary dependency chains, and every link is invalidated by the base commit. The effect class is pure and the command is deterministic (version 1.1.0).

Body syntax

@highConfidenceClaims containerFilter
source: $claims
predicate:
  return row.confidence >= $threshold && row.status !== "superseded";

Worked example

A derived view of high-confidence, non-superseded claims:

@highConfidenceClaims containerFilter
source: $claims
predicate:
  return row.confidence >= $threshold && row.status !== "superseded";

The analyzer records $claims as the container read and $threshold as a value dependency. When either the source container or the threshold changes, the view becomes dirty and downstream wires become dirty transitively — a correction that adds a previously missed legal exception creates a new base revision, invalidates the filter, and invalidates the JavaScript wire that groups the kept records.
