Wire types

containerRemove

containerRemove stages deletion or tombstone operations under an explicit identity contract.

What it does

Use it when a record leaves the current canonical view but history must remain auditable. The body names a target and the items (by identity) to remove or tombstone.

How it works

The command normally creates a tombstone or a new revision rather than erasing history, so replay and audit remain possible; it does not rewrite the past. Every accepted item is recorded in an append-only history with the record it replaced, so an earlier assertion and its source spans stay retrievable by revision after a replacement, while the canonical view may change. The patch is staged against the revision visible at the start of the epoch and committed at the barrier. The effect class is container_patch and the command is deterministic (version 1.1.0).

Body syntax

@retract containerRemove
target: claims
items:
  - id: claim_017

Worked example

Retracting a superseded claim from the canonical view without erasing it:

@retract containerRemove
target: claims
items:
  - id: claim_017

The patch tombstones claim_017 in the current revision; the record and its source spans remain retrievable by revision for audit, and downstream views that depended on the claim are invalidated transitively.
