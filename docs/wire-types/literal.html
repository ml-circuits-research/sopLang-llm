Wire types

literal

literal produces a literal scalar, JSON value, or text body: the body is the value, published unchanged.

What it does

A literal wire publishes its body as a value. It is useful for constants and small structured values embedded in the circuit. Large source documents do not belong in a literal body; they stay in the source store and are referenced through an input wire or a source identifier, so the circuit never duplicates large text and provenance stays stable.

How it works

The executor parses the body once: it trims whitespace, returns the empty string for an empty body, and otherwise attempts JSON.parse. A body that parses as valid JSON becomes that JSON value (a number, string, boolean, array, or object); a body that does not parse is returned as text. The command is pure and deterministic (version 1.0.0): no dependencies and no execution beyond parsing.

Body syntax

Either a scalar or a JSON value:

@answer literal
42
@config literal
{ "threshold": 0.8, "labels": ["yes", "no"] }

Worked example

A literal threshold feeding a jsEval filter:

@minimum literal
3

@answer jsEval
return [1, 2, 3, 4, 5].filter((n) => n >= $minimum);

$minimum is bound to 3, so the filter keeps [3, 4, 5]. The threshold is a named constant rather than a value buried inside the JavaScript.
