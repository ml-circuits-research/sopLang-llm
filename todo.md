# sopLang-llm project plan

The project fine-tunes a small code-capable language model to compile problems into SOP Lang circuits instead of generating final answers directly. The circuit is executed by a runtime that resolves dependencies, delegates deterministic work to JavaScript, calls explicitly declared tools or neural judgments, and returns a traceable result. Persistent typed containers let the model process sources that exceed its context window.

### Review gate - 2026-09-17 (closed)

The checked items above record implementation milestones, not full semantic conformance. Review against the vision handbook and DS002/DS004/DS005 found the defects below despite `npm test` passing all 106 tests on Node.js v22.23.2. Isolated runtime probes reproduced the stated failures, including a nonterminating probe that required external termination. Every defect is now fixed, the affected specifications and HTML pages were updated in the same change, and the standard commands whose observable contract changed were versioned from `1.0.0` to `1.1.0` (`jsEval`, `modelCall`, and all container commands). The changed semantics are verified by the test suite and by an end-to-end gate probe that exercises each acceptance statement below; because the repository ships no generated dataset yet, the version increment has no training data to migrate.

- [x] **P0 — Bound and isolate generated JavaScript execution.** Generated code now runs in a private guest realm inside a worker thread. Values cross the realm boundary only through the versioned value profile of `runtime/values.mjs`, so no host object reaches the guest and `circuit` is a guest-realm facade whose operations are replayed onto the real transaction. The synchronous part of a call runs under the realm's script timeout and the worker is terminated at the JavaScript deadline, so `while (true) {}` and `while (true) { await Promise.resolve(); }` both end as structured `budget_exceeded` outcomes within the process, and a completed 30 ms loop reports its consumed JavaScript time against the request budget. Acceptance: `tests/sandbox.test.mjs` (isolation, deadline, cumulative accounting) and the gate probe's P0 statements.

- [x] **P1 — Enforce immutable dependency and container snapshots.** Request inputs are copied and frozen at run start, container records are frozen and snapshots and views are deep copies, staged patch items are copies, and a JavaScript wire receives copies of its dependency values. `$rows.push(2)` no longer reaches the caller array or a sibling observation, and a tampering body cannot change a stored record or a container revision. Acceptance: `tests/sandbox.test.mjs`.

- [x] **P1 — Activate container contributions for ordinary value reads.** `runtime/graph.mjs` links a value read of a container declaration into the node's read set, so a `jsEval` or `modelCall` body reading `$c`, a filtered read, and a direct container output activate the contributing writers, observe the committed revision, and invalidate on the next commit. Acceptance: `tests/kernel.test.mjs`.

- [x] **P1 — Propagate explicit invalidation downstream.** `circuit.invalidateWire` now invalidates the named wire and every affected consumer, including transitive dependencies, while `circuit.invalidateDownstream` invalidates only consumers. A refreshed model observation reaches the output that depends on it. Acceptance: `tests/kernel.test.mjs`.

- [x] **P1 — Make grouped container commits atomic.** `ContainerStore.commit` applies every patch of a group to a working copy and publishes the group only after it is fully accepted, so a rejected batch leaves records, tombstones, history, and revision counters unchanged and a reused store stays clean. Acceptance: `tests/containers.test.mjs`.

- [x] **P1 — Support composed container filters.** A filter source may be a derived view: the runtime binds the source wire value, keeps the base container name and revision as provenance, and invalidates every link of a base container → filter → filter → scalar chain. Acceptance: `tests/containers.test.mjs`.

- [x] **P1 — Preserve historical assertions across upserts.** Every accepted item is recorded in an append-only per-container history with its identity, source wire, resulting revision, and the record it replaced, and history entries are retrievable by revision, so a replacement or a merge never erases the earlier assertion or its source spans. Acceptance: `tests/containers.test.mjs`.

- [x] **P2 — Enforce set membership identity.** A set deduplicates by canonical or declared identity within a patch, across grouped patches, and across revisions. Acceptance: `tests/containers.test.mjs`.

- [x] **P1 — Separate instruction-text and JavaScript dependency analysis.** `runtime/dependencies.mjs` provides a JavaScript analyzer that ignores string literals, comments, regular-expression literals, and property names and understands spread expressions, plus an instruction-text analyzer that reads `$name` wherever it appears, so `What's $x?` reaches the model with `x` bound while `/$ghost/` and `obj.$price` invent no dependency. Acceptance: `tests/dependencies.test.mjs`.

- [x] **P1 — Make schema acceptance fail closed.** `runtime/schema.mjs` publishes the versioned profile `soplang-json-schema 1.0.0` with the constraint and annotation keyword sets, enforces every advertised constraint, resolves boolean schemas, and reports any keyword, type name, or constraint form outside the profile as `unsupported_schema` before accepting a record or an output. Acceptance: `tests/schema.test.mjs`.

- [x] **P1 — Complete the structural transaction protocol.** `circuit.getDefinition` returns the actual command identity, definition hash, and body of the current revision, `circuit.listDefinitions` returns the definitions matching a prefix, both record structural reads that participate in invalidation, and a wire that stages operations without `circuit.commit` publishes nothing. Transactions carry an intent hash over parent revision, origin wire, structural reads, and operations; an identical retry against the same parent revision is idempotent, re-adding an unchanged definition is a no-op, and reusing an identifier with different content is rejected. Every structural change advances the circuit revision counter. Acceptance: `tests/metaprogramming.test.mjs`.

- [x] **P1 — Bind replay to the recorded computation.** Exact replay matches the wire definition hash and the hashes of the dependency values, records the substituted observation with the provenance of the entry it replayed, and rejects a mismatch as `replay_mismatch` instead of returning a stale answer. Acceptance: `tests/trace.test.mjs`.

- [x] **P1 — Record sufficient trace and revision evidence.** Success and rejection records carry the circuit revision, epoch, wire, command identity and version, definition hash, dependency identities, timing, output hash, staged effects, and transaction details; a JavaScript exception records its wire and dependencies and leaves earlier progress in the trace; same-size redefinitions advance the revision. Acceptance: `tests/kernel.test.mjs`, `tests/metaprogramming.test.mjs`, and `tests/trace.test.mjs`.

- [x] **P1 — Normalize parser failures into run outcomes.** `CircuitRuntime.run` parses inside its error boundary, so a malformed program returns a failed outcome with a stable `parse_error` code, a recorded error entry, and empty outputs instead of rejecting the call. Acceptance: `tests/kernel.test.mjs`.

The installable wire loader and the context adapter remain planned work covered by the unchecked items above, not regressions. Template instantiation is also still pending and must receive an executable acceptance gate before any template or recursive-template example is admitted.

### Pilot source decision - 2026-09-17

The seed books were measured rather than sampled by impression. Each of the six books under `vision/` contains exactly 1000 problems, and the answer labels were counted in the DOCX XML: `Mathematical_Thinking_1000_Problems_Grades_1-4_EN.docx` carries 1000 `Answer:` labels with 1001 `Abstract model` and 1001 `Step-by-step solution` blocks, `World_as_a_System_1000_Reasoning_Problems_Grades_1-4_EN.docx` carries 1000 answers with 1001 `Formal model` blocks, `Common_Sense_for_Adults_1000_Problems.docx` carries 1000 answers with 1000 step-by-step solutions, `Decompose_to_Solve_1000_Problems.docx` carries 1000 combined answers with 4700 minimal-input subproblem fields, `Adult_Reasoning_and_Everyday_Knowledge_Course.docx` carries 1000 answers with 1000 stems and 40 unresolved `{x}` placeholder tokens that require quarantine, and `Logical_Reasoning_Types_Course.docx` carries 1001 answers with 1001 stems.

`Mathematical_Thinking_1000_Problems_Grades_1-4_EN.docx` is the pilot source. It scores highest on both properties a first pilot needs: every problem ends in a single checkable value with no outside knowledge, and the book prints an `Abstract model (also useful for code representation)` line that already states the symbolic recipe, which is the compilation target the student is trained to emit. Its roughly 150-200 distinct templates give far more latent-plan diversity per 1000 items than `Common_Sense_for_Adults` (about 20 recycled templates), `Adult_Reasoning_and_Everyday_Knowledge_Course` (about 100 schemas in 10 near-duplicate variants), or `Logical_Reasoning_Types_Course` (about 100 schemas whose answers are often prose appraisals). Known defects to quarantine or handle are the Romanian `Da.` answer and the `lei` currency in localization artifacts, the few templates that admit several valid answers and print one, and the near-duplicate variants that must not straddle a split.

`World_as_a_System_1000_Reasoning_Problems_Grades_1-4_EN.docx` is the secondary pool: 200 family-by-grade schemas with fictional closed premises and a `Formal model` line that names the algorithm, but its route family prints one winner while the sampled instances tie, and its Grade 3-4 items bundle two or three sub-answers. Its compilation status is recorded under "Second book compiled - world as a system (2026-09-18)" below. `Decompose_to_Solve_1000_Problems.docx` is reserved for decomposition-depth and atomicity supervision after the pilot, because its 1000 items collapse to 10 templates and about a fifth are formulation judgements rather than values.

The pilot pipeline, to run after the readiness gates below are closed:

1. Extract the book with canonical provenance: raw and canonical hashes, paragraph and table offsets, chapter and problem identity, template identity, and a per-item rights and quarantine record.
2. Split by template, not by problem, so the five parameter variants of one template stay in one split and held-out evaluation measures an unseen latent plan.
3. Implement independent oracles for a first family set, validated by reproducing the book's printed answers for the book's own parameter sets; a disagreement moves the item to rejected with a recorded reason instead of inheriting the printed key.
4. Compile each problem into a self-contained circuit: the reference parse runs at build time, its values become the `slots` literal of the instance, the remaining computation is deterministic `jsEval` work over those values, and the executed answer is compared against the independent oracle. A dataset circuit carries no `input` wire and no `modelCall` wire, because the compiler already read the problem.
5. Accept only candidates that execute, delegate the computation symbolically, match the oracle, and pass schema, provenance, and leakage checks; persist accepted and rejected examples with traces.
6. Lock the 1000-example manifest and its report to the source, split, template, runtime and command versions, and keep the deliberately ambiguous and non-decomposable items in the rejected set with their reasons.

### Dataset contract revision - 2026-09-17 (owner directive)

The owner directed that dataset circuits must not use `input` wires and must not contain wires that call a model: the SOP Lang file is itself generated by a model that already read the problem, so an input wire would only re-state data the compiled plan carries and a `modelCall` parse stage would ask a model to re-parse its own input. The dataset contract was changed end to end in the same session:

- `solution.sop` is now the compiled plan of its instance: a `slots` `literal` wire carries the values the compiling model extracted from the statement, an optional `facts` `literal` wire carries external knowledge the computation reads, and the `answer` wire performs the deterministic `jsEval` computation. The reference parse of the family runs at build time and materializes those values; nothing the runtime executes performs a semantic parse.
- The family contract dropped `parseInstruction`, `promptVocabulary`, the `program` field, and every embedded prompt; families declare `parse`, `solve`, `render`, `compute`, `explain`, optional `facts`, and optional `sharedPremise`. The loader rejects any family whose compiled program declares an `input` or `modelCall` wire, whose answer wire is not `jsEval`, or whose knowledge fact is asserted through a substring guard.
- Because a compiled circuit embeds its instance values, the latent plan is measured by the plan fingerprint (the facts and compute body) rather than by circuit text: the report and the manifest index count distinct plans, and the evaluation holdout clusters templates by shared plan fingerprint with a writer assertion that no eval plan occurs in a training row.
- The pilot gained the English-only gate, the `sharedPremise`/`unresolved_reference` contract, the structural fact dependency check, the source blemish scan, the guarded oracle path, and the sandbox and dependency fixes recorded above.

### Rejected candidates recovered (2026-09-18)

Three mechanisms were added to the dataset contract, all covered by `npm test`:

- `clarification` — a case may declare a sentence that joins the solver-visible statement as an `Additional information.` line, and the declaration may be a function of the problem, because one printed template covers many variants whose missing information differs.
